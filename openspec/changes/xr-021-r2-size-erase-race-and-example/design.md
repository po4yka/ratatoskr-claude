## Context

XR-021 CONTRACTS.md R2-07, R2-04 and R2-10 are the source of truth. This file records the local decisions.

## Decisions

- The reference check has one implementation, `blob_protocol::referenced_among`, over the seven columns that hold a blob key (`exports.blob_ref`, `extracted_artifacts.blob_ref`, `project_sources.blob_ref`, `content_parts.blob_ref`, `artifact_versions.blob_ref`, `assets.blob_ref`, `projects.instructions_blob_ref`). The row-removal transaction (`retain_blobs_still_referenced`) and the eraser both call it, so planning-time and erase-time agree by construction.
- Acquisition order, documented in the module: the tenant lock first (for the importers the archive account id, for the eraser the request's tenant reference), then digest locks in ascending digest order. No code path takes a digest lock and then a tenant lock.
- The eraser handles one item per transaction: lock tenant, lock digest, recompute references, then either mark `retain_shared` or erase and mark `purged`, and commit while the lock is held. The filesystem erase is idempotent, so a commit failure after the erase converges on retry. `PrivacyDeletionExecutor::with_erase_gate` is the blocking seam the interleaving tests use: it parks the eraser after the re-check and before the erase, while it holds the digest lock, either at every blob (`EraseGate::new`) or at one digest (`EraseGate::for_digest`).
- The receipt streams an archive of up to the archive limit and does not keep the bytes, so a missing blob there cannot be stored again: `record_verified_platform_archive` fails with `ReceiptError::Registration(BlobRegistrationError::Erased)`, which the HTTP boundary maps to the existing internal error envelope (the Platform retry re-delivers the archive). The importers hold the bytes (the parser evidence, the Artifact payloads) and store them again; the registration failure of an importer is `ReparseError::Registration`, which is not a permanent failure, so the run is retried.
- Presence is checked with `BlobStore::locate` (metadata only), not `verify`, so a registration never re-hashes a multi-gigabyte archive.
- The size guard measures the serialized `EventEnvelope`, the exact bytes the pump publishes. The guard lives in `ImportProjection::publish` and measures every subject fact (project, conversation, Artifact); the import head is small and unguarded. A skipped fact is counted in `Omitted::too_large`, which names a `fact_too_large` gap on the head, so the archive is never announced as complete, and the operation report adds `ai_archive.facts.too_large` beside the one `ai_archive.import.incomplete` that already applies. The limit reaches the importer through `InitialImportWorker::with_max_event_bytes` and `ReparseEngine::with_max_event_bytes`, defaulting to `DEFAULT_MAX_EVENT_BYTES` so no constructor changes. The facts a privacy deletion re-announces for surviving subjects are not guarded at enqueue time; the pump's publish-time check is their backstop.
- The pump reads the server limit from the connected client (`server_info().max_payload`) and subtracts 1 KiB of header headroom. A row whose stored body is larger is marked `undeliverable_at = now()` with `last_error = 'payload_too_large'` in one statement, and the pass continues with the next row. The `(event_type, payload_digest)` unique key is unchanged.
- The operator example binds only the ports in the workspace table (operator 9086, receipt 8097) and names the seed at `/etc/ratatoskr/claude.nkey`.
