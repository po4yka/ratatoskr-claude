## Context

XR-021 CONTRACTS.md R3-01, R3-03, R3-04, R3-07, R3-11, R3-16 and R3-19 are the source of truth. This file records the local decisions.

## Decisions

- The inbox prefix is one `const INBOX_PREFIX: &str = "_INBOX_claude"` beside the subject constants of the outbox, applied through one function that builds the connect options, so the test calls the same function the pump does.
- The pump keeps its public signature `publish_pending_once(endpoint, seed_path)`. The publisher holds a `tokio::sync::Mutex<Option<HeldConnection>>`, where `HeldConnection` is the client, its `JetStream` context and an `AtomicBool` that the connection's `Event::Closed` callback raises. A pass first asks the database whether a row is pending and returns `Ok(0)` without touching the network when none is; otherwise it uses the held connection, replacing it when the flag is raised. async-nats reconnects by itself while merely disconnected, so only a closed client (one it cannot recover from) is replaced.
- A pass that fails against the broker (connect, timeout or a refused publish) also drops the held connection. The next pass then creates a new one and reads the nkey seed file again, so a rotated seed takes effect without a restart; a held client would otherwise keep reconnecting with the credentials it was created with. The seed file is read when a connection is opened, not on every pass.
- Readiness of the report publisher is the publisher's own verdict (`OutboxPublisher::is_healthy`), shared by its clones: a pass that talks to the broker sets it to healthy or failing, and a pass over an empty outbox, or over rows inside their retry delay, makes no network call, learns nothing and leaves it unchanged. A fresh publisher is healthy. Accepted trade-off: a service whose broker is unreachable, or whose seed file is unreadable, reports ready until the first fact is pending (the first import) and only then reports the fault. Proving the broker on an idle pass would need the network call R3-07 rule 1 forbids; the fault is visible on `/health/ready` as soon as it can matter, and it clears with the first publish that succeeds.
- The account row is inserted in the receipt transaction on the Platform path only, with `on conflict (account_id) do nothing`, exactly the statement of CONTRACTS.md R3-04 rule 1. `ensure_account` keeps its select for the tenant-token path.
- `Kind::AccountUnmapped` is a new member of the closed `Kind` set in `fault.rs`; the mapping happens where `platform_claims` finds no mapping, and `UnknownTenant` remains the tenant-token result.
- The selector of `process_pending_once` adds `failed` runs that have a bound operation with `reported_at is null`; the report it enqueues is the one `mark_permanent_failure` enqueues, so both paths share the report builder. `mark_permanent_failure` logs `class` and the run id and never an archive path, name or content.
- The example role file and the example share the role, database and port by a test that parses both.
