## Decisions

- The ingest runs inside `prepare_initial_import`, outside the import transaction, because it writes to the blob store. Its outcomes travel in `PreparedInitialImport::knowledge_outcomes` in file order, one per parsed knowledge file, so the report and the persistence read the same list. A `StoreError` becomes `ReparseError::KnowledgeIngest`, which `is_permanent_import_error` does not list, so the run stays in its state and the next pass repeats the ingest. A knowledge file whose byte array is empty is a reference without bytes (the blob store refuses an empty blob, and a retry could never succeed).
- A source row only moves up in quality: verified, then quarantined, then reference only. A later export that carries the bytes upgrades a source an earlier export only referenced, and a later export that only references the file leaves the verified bytes alone. `projects.local_backup_status` is recomputed from the project's source rows after the upserts: `locally_backed_up` exactly when the project has at least one source and all are verified.
- `register_blobs` lists the evidence blob of every verified or quarantined knowledge file and stages every file's bytes, so an eraser that removed a blob between ingest and registration causes it to be stored again.
- Versions follow ChatGPT `23bbcb4`. The digest of a project is the digest of its name, description and instructions. The digest of a conversation is the digest of its title, project reference, creation time and the ordered messages with their parts, and not of the parser stamp or the inert unknown fields, so a newer parser that reads identical content presents the same version. `projects.content_digest` and `conversations.content_digest` name the content the shared row holds now.
- The conversation upsert of the import writes the newest title, project reference and parser stamp (a stamp changes only when the content digest changes, so an unchanged content keeps the published digest stable). Content parts keep their existing rule, first part at an index wins, which is what makes a rebuild from the retained versions in export order equal an import of only the retained exports.
- Reparse loads, per conversation, the digest the export itself presented and compares it with the digest of the parsed conversation, instead of comparing the title with the shared row.
- `privacy_deletion/restore.rs` runs in phase A after `delete_inventory_rows`: it drops the versions of records that no longer exist, finds every surviving project and conversation whose current digest no retained export presented, writes a project from the newest retained version and rewrites a conversation (its content parts, messages and header) from the retained versions in export order, removes the project sources no retained export observed, recomputes `local_backup_status`, and prunes the snapshots no export names. The blob of a removed source is a child item of the inventory (erase unless a remaining row references it), decided by the same closure as every other child blob.
- The survivor decision (`announced_under_deleted`) reads the outbox before the facts of a deleted archive are removed, so the facts that are removed from a retained aggregate (they carry the deleted export's text) are deleted after the survivor facts are enqueued. The re-announced fact names the earliest retained export whose observation carries the digest of the current content.
